三 研究内容
论证提出课题研究的总体思路，拟开展的主要研究内容及内涵，说明各部分研究内容之间的相关关系。

3.1 总体研究思路
本课题围绕“链下交易事实可信化、链上结算自动化、合规信息最小化”展开，目标是在 C2C 场景下形成一套兼顾安全性、隐私性、可执行性与可扩展性的半去中心化交易方法。研究总体遵循“问题导向—机制设计—系统实现—评估优化”的路径，重点解决链下事实难以被链上可信接收、隐私保护与合规要求难以兼容、以及跨平台场景下验证机制复用性不足等核心问题。

3.2 关键痛点与研究任务
表2 关键痛点—研究任务对应关系

| 关键痛点 | 研究任务 |
|---|---|
| 链下支付或交易事实难以直接被链上可信接收 | 构建跨域可信证明机制，将链下事实转化为链上可验证证据 |
| 隐私保护与合规审计存在天然张力 | 设计“最小披露、按需验证、可审计留痕”的协同机制 |
| 多参与方场景下信任边界不清晰、责任难追溯 | 建立可验证的责任划分与争议处理机制 |
| 交易流程对人工判断依赖高、结算一致性不足 | 形成规则驱动的自动结算与超时回退机制 |
| 不同支付场景差异大、系统扩展成本高 | 抽象通用验证框架，支持多平台低耦合扩展 |
| 性能、成本与安全收益难量化 | 构建统一评测体系，形成可比较的优化依据 |

3.3 研究任务、拟采用方法与预期结果
表3 研究任务—拟采用方法—预期结果

| 研究任务 | 拟采用方法 | 预期结果 |
|---|---|---|
| 可信证明机制设计 | 从协议层抽象链下事实到链上证据的映射关系，统一证据表达与校验逻辑 | 形成可复用的可信证明模型与规范化证据格式 |
| 隐私与合规协同设计 | 对交易数据进行分层分类，采用最小披露与条件化核验策略 | 在不暴露敏感原文的前提下满足必要合规核验需求 |
| 自动结算机制设计 | 建立状态机与触发条件模型，定义放行、回退、超时与争议流程 | 形成可确定执行的自动结算流程，降低人工干预依赖 |
| 可扩展验证框架设计 | 采用模块化与接口化思路分离通用能力与场景能力 | 支持新场景快速接入，降低系统演进成本 |
| 安全与鲁棒性设计 | 基于威胁建模识别重放、篡改、伪造与串谋等风险并设计防护策略 | 形成覆盖主要风险面的安全控制与应对策略 |
| 性能评测与优化 | 以时延、成本、吞吐与正确性为核心指标开展系统评测与对比分析 | 输出量化评估结论与优化方向，为后续迭代提供依据 |

3.4 各研究内容之间的关系
本课题各项研究内容具有明确的逻辑递进关系：
1. 先通过可信证明机制解决“链下事实如何被可信表达”的问题；
2. 再通过隐私—合规协同机制解决“证明可用但不过度暴露”的问题；
3. 在此基础上由自动结算机制实现“证明结果可执行”；
4. 最后通过可扩展框架与量化评测实现“可持续演进与可验证优化”。

因此，本研究并非对单一模块进行局部改进，而是从方法层面构建一个兼顾可信性、隐私性、执行性和扩展性的整体性方案。

3.5 创新性体现
为保证创新点与当前工程实现一致，以下内容均对应现有代码、测试与数据分析结果。

1. 提出“通用 TLSN 校验内核 + 平台验证器插件化”的跨平台可扩展架构
本课题将 TLSN 的通用密码学校验（chainId、sessionId、commitment opening、签名恢复）与平台业务语义（字段匹配、金额/币种/状态校验、平台交易号防重放）解耦：核心合约负责统一校验与调度，平台差异由 `IPlatformVerifier` 实现并通过 `platformId` 注册。当前已实现 Alipay（单 proof）与 Wise（双 proof）两条链路，新增平台无需改动核心结算合约。

2. 提出“订单上下文全量绑定 + 会话级防重放”的抗挪用证明机制
本课题将 `orderBindingHash` 绑定到合约地址、链 ID、交易双方、产品与订单编号、资产方向、金额、汇率、汇率版本、截止时间及账户哈希，并由 Verifier 对 `commitmentsHash + orderBindingHash` 进行签名。链上同时执行 sessionId 去重、交易号去重、跨订单绑定校验，有效阻断“跨订单复用 proof”“抢跑提交他人 proof”“旧签名迁移新订单”等攻击路径。

3. 提出“链下账户明文校验 + 链上双哈希最小披露”的隐私一致性方案
针对收付款账户信息，系统仅在链上存储 `nameHash + idHash`，明文仅在 Verifier 内存态 transcript 中做 `keccak256` 一致性校验。扩展端进一步将账户校验范围从 `results` 与 `commitmentOpenings` 过滤，避免账户字段在证明结果中二次泄露，实现“可验证结算”与“敏感信息不上链”的并行成立。

4. 提出“汇率版本快照（rateVersion）+ 订单绑定”的抗价格漂移结算机制
商家可持续发布新汇率，但每笔订单在下单时固化 `rateVersion` 并写入绑定哈希。后续验证严格按订单快照版本结算：旧订单不受新汇率影响，错误版本 proof 直接失败。该机制将“报价可更新”与“历史订单价格确定性”同时落地。

5. 提出“运营规则上链门控”的可审计准入机制
本课题将营业时间表、手动开关、汇率有效期、单笔限额、产品激活状态统一纳入链上门控，订单能否进入系统由合约确定性判定，而非链下人工判断。该设计把平台运营策略从“平台规则”升级为“可验证规则”，增强了执行一致性与可追溯性。

6. 提出“超时双倍赔付 + 队列自动清理”的违约约束机制
在 FIAT 流程中，当商家超时未完成付款，买家可触发 `2x` 赔付；同时系统通过队列化 `_cleanupExpired` 自动清理过期订单并同步释放状态。该机制将违约成本显式化、自动化，减少对人工仲裁的依赖，提高异常路径的可执行性。

7. 构建“可量化的 TLSN 性能评估方法”并验证选择性披露收益
基于 `data_analysis` 的多组 sweep 实验（latency/bandwidth/download/proof_reveal）可见：在相同参数下，native 路径总体时延显著低于 browser；以 `proof_reveal` 为例，披露比例从 100% 降至 10% 时，browser 平均总时延由约 28.99s 降至 21.89s，native 由约 16.79s 降至 13.68s，下载量亦同步下降。该结果为“最小披露不仅提升隐私，也能改善性能成本”提供了工程证据。
